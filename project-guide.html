学习演示中的项目用途
当前代码的目标是跑通训练 → 保存 → 全新加载 → 一致性验证。8 个虚构项目各有两种问法，共 16 条样本；没有独立验证集，不能据此判断实际业务准确率。

现在的项目结构

训练和推理已合并；模型下载放进 Python 安装脚本。主程序在终端输出进度和验证结果，默认把 adapter 直接保存到 outputs/adapter。

运行流程

安装一次，训练与推理共用主程序
  1. 准备 WSL 与 Windows AMD 驱动

    按 INSTALL.md 准备 Ubuntu 24.04、Python 3.12 和 WSL 配额；系统安装脚本要求已有可用的 Windows 驱动与 /dev/dxg。

  2. root 运行 install_rocm.sh

    配置 AMD APT 软件源和优先级，安装 HIP、数学库和 ROCDXG，设置动态库搜索路径，最后在终端运行 rocminfo。

  3. 普通用户运行 install_python.sh

    检查 Python 版本，创建 .venv，加载 env.sh，安装 pip / uv，下载并校验配套的 AMD Torch 和 Triton wheel。

  4. uv 安装依赖，下载固定版本模型

    执行 uv pip install 两个 wheel 和 requirements.txt，再执行 pip check。最后通过 snapshot_download 将模型放进 models/Qwen3.5-0.8B。

  1. source env.sh → python lora_demo.py

    加载环境，检查本地模型和输出路径；确认 ROCm GPU 可用，选中 RX 7700 XT，并校验 GPU 矩阵计算与反向传播。

  2. 生成数据，先记录基础模型的回答

    make_data() 在内存中构造 16 条样本；对青禾、星桥、海棠三个问题记录训练前回答。

  3. 注入 LoRA，执行训练

    基础权重冻结，只训练 LoRA；micro batch 为 1，累积 4 次梯度后更新一次。检查 loss、梯度和参数是否实际变化。

  4. 保存到 outputs/adapter，再从磁盘加载

    保存 LoRA 与 tokenizer 后释放旧模型及优化器，新建基础模型并挂载 adapter；比较一条输入的末位置 logits 和三个问题的生成 token。

  1. source env.sh

    激活项目 .venv，设置 ROCm 库与缓存路径。

  2. 加上 --adapter 与 --prompt

    同一个 lora_demo.py 进入推理分支，跳过训练；仍检查本地基础模型和 GPU。

  3. 基础模型 + adapter + 保存的分词器

    基础模型来自 --model，adapter 与 tokenizer 来自 --adapter 指定目录。

  4. 终端打印一次回答

    采用固定的内部项目查询助手 system 提示词和贪心生成，最多生成 32 个新 token。

核心代码拆解

lora_demo.py

主程序没有额外的训练框架封装，数据、训练循环和保存验证都在一个文件里。按下面的函数顺序阅读即可理解它。

parse_args()读取 5 个命令行参数，检查正数步数、本地模型 config.json、adapter_config.json 和输出目录，避免覆盖已有 adapter。
select_device()检查 torch.version.hip 和 torch.cuda.is_available()，选中名称包含 7700 XT 的设备；对照 CPU 验证矩阵乘法，再检查非零且有限的反向梯度。
load_model()用 Qwen3_5ForCausalLM 加载本地文本模型，显式使用 FP32、eager attention 和 local_files_only=True，检查必需权重，关闭训练 KV cache。
messages()把全局 SYSTEM_PROMPT 与一个用户问题组合成 messages，让训练和推理共用同一套提示词结构。
make_data()构造 8 个虚构项目的用途，每个两种问法，共 16 条。聊天模板生成完整 token，前缀 labels 填 -100，仅对 assistant 回答和结束符计算 loss。
batch()把单条样本变成 GPU 上的 input_ids、attention_mask 和 labels；batch size 固定为 1，没有额外数据加载器或 padding 管线。
predict()应用聊天模板，关闭思考模式，贪心生成最多 32 个新 token；同时返回 token ID 和去掉首尾空白的答案文字。
train_demo()记录训练前答案，注入并训练 LoRA，确认参数更新，保存 adapter 与 tokenizer；释放旧对象，重新加载后校验 logits 和逐 token 生成结果。
main()设置随机种子 42、CPU 线程数 4，选择 GPU；有 --adapter 就推理，否则调用 train_demo()。
16内置训练样本
20默认优化器更新次数
8 / 16LoRA rank / alpha
4梯度累积次数

这些数字是当前代码的默认配置，不是本次重新训练得到的测量值。其他设置包括学习率 2e-4、dropout 0、AdamW weight_decay 0、梯度裁剪阈值 1.0，以及梯度检查点。

保存验证的边界：脚本要求重载前后的 logits 在 rtol / atol = 1e-4 内接近，且三个探针问题的生成 token 完全一致。它没有断言回答必须等于 expected，也没有自动生成准确率、JSON 报告或训练数据快照。

uv 与依赖版本

按当前安装脚本的实际用法

本项目使用 uv 管理 Python 包的安装与依赖版本。requirements.txt 固定包版本，安装脚本下载两个配套的 AMD wheel，再交给 uv pip install 一起安装到 .venv。

版本从哪里来requirements.txt 中的 == 约束固定 Torch、Triton、Transformers、PEFT 和间接依赖版本；pip 26.2.1、uv 0.13.0 在安装脚本中固定。
为什么有本地 wheel本项目需要指定的 AMD ROCm 构建。安装时把 Torch 和 Triton 的 .whl 同时传给 uv，提供通用包索引中没有的匹配构建。
安装前后做什么curl 断点续传安装包，SHA256 校验通过后才改为正式文件名；uv 安装完成后执行 python -m pip check 检查依赖兼容性。
当前管理方式是 uv pip + requirements.txt；当前没有 pyproject.toml、uv.lock，也没有使用 uv sync 工作流。
源码怎么保存Git 记录源代码、文档和本页面的提交历史。uv 管理 Python 环境与依赖版本，Git 管理项目文件的版本历史。
安装脚本内部使用的命令形态
uv pip install "$torch_whl" "$triton_whl" -r requirements.txt
python -m pip check

这里的两个 shell 变量由 install_python.sh 设置。首次安装应执行完整脚本；仅单独安装 requirements.txt 不能代替 AMD wheel 的下载和配套安装。

运行与修改

环境就绪后，在 Ubuntu-24.04 的 Bash 执行
默认训练、保存并验证重载
cd /home/nnnnnn/lora
source env.sh
python lora_demo.py

默认输出目录是 outputs/adapter，采用固定路径。该目录已包含 adapter_config.json 时，需要换一个输出目录。

为下一次训练指定另一个目录
cd /home/nnnnnn/lora
source env.sh
python lora_demo.py --steps 20 --output-dir outputs/another-adapter
加载已有 LoRA，问一个问题
cd /home/nnnnnn/lora
source env.sh
python lora_demo.py \
  --adapter outputs/adapter \
  --prompt '项目青禾的用途是什么？'

命令行支持哪些参数

--model本地基础模型目录，默认 models/Qwen3.5-0.8B。主程序只加载本地文件，不会在运行时自动下载。
--steps优化器更新次数，默认 20，必须大于 0。每步处理 4 个 micro batch。
--output-dir训练产物目录，默认 outputs/adapter。adapter 和 tokenizer 直接保存在这个目录内。
--adapter指定已有 LoRA 目录，进入只推理模式，跳过训练。
--prompt只推理模式使用的问题，默认“项目青禾的用途是什么？”。它不会修改训练数据。

想换成自己的数据

修改 make_data() 中的 facts 或实现自己的数据读取逻辑。当前没有外部 JSON / CSV 数据入口，也没有独立验证集。

想调整训练行为

rank、alpha、学习率在 train_demo()；梯度累积在 GRADIENT_ACCUMULATION；提示词在 SYSTEM_PROMPT；生成长度在 predict()。

常见疑问

几个关键区别
adapter 可以单独当作模型运行吗？

不能。LoRA 权重保存的是新增参数，推理仍需基础模型、adapter 配置和匹配的分词器。当前项目没有执行模型合并或 GGUF 导出。

为什么 AMD 显卡代码里出现 torch.cuda？

ROCm 版 PyTorch 也通过 torch.cuda 这套接口操作 GPU。代码另用 torch.version.hip 检查 ROCm，因此 cuda:0 这个设备接口名称并不意味着使用了 NVIDIA 显卡。

模型有图片、视频配置，项目会训练视觉部分吗？

主程序选择 Qwen3_5ForCausalLM，只加载文本模型。官方目录保留多模态配置和权重文件，视觉相关权重由文本模型忽略，没有图像或视频训练流程。

现在的 report.json 和训练日志在哪里？

当前主程序只向终端输出 loss、训练耗时、PyTorch 峰值 allocated 显存、前后回答和验证结果，不自动写 JSON 报告或日志文件。页面生成时也没有 outputs 或 logs 目录。

source.json 还会被新安装脚本使用吗？

不会。模型目录中现存的 source.json 是之前下载流程留下的来源清单。当前安装脚本把仓库与 revision 直接传给 snapshot_download，主程序和安装脚本都不读取这个清单。

Git 提交会包含模型、缓存和 LoRA 权重吗？

当前 .gitignore 排除了 models、outputs、cache、downloads、logs 和 .venv。Git 提交保存源码与文档；需要保留的基础模型和训练结果应另行备份。

更换模型或显卡，改命令行就够了吗？

--model 只指定本地路径，代码仍使用 Qwen3_5ForCausalLM，硬件选择也要求名称包含 7700 XT。换模型架构或显卡时，需要相应调整代码、安装环境并重新验证。
